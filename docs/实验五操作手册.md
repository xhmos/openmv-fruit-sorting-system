## 三、第 1 步：数据采集

报告要求 ≥200 张、每类 ≥50 张、320×240。

```powershell
cd C:\Users\10149\Desktop\openMV
.\train_env\Scripts\python.exe train\collect_dataset.py --per-class 60
```

**操作方式**：弹出摄像头窗口后
- 按 `0` / `1` / `2` 切换类别（对应 `train/classes.txt` 里的 apple / orange / banana）
- 按 `空格` 拍一张
- 按 `a` 开自动连拍（每 0.45 秒一张，拍满 --per-class 自动停）
- 按 `q` 退出

**采集要点**（直接可以写进报告「实验步骤」）：
1. **光照稳定**：关掉顶灯直射，用侧光或漫射光，避免果实表面高光过曝
2. **背景单一**：纯色桌面或白纸垫底，减少与果实颜色接近的干扰
3. **样本多样**：每类至少覆盖正视、侧视、不同距离、轻微遮挡、不同旋转角度
4. **数量均衡**：三类张数尽量接近，否则模型会偏向样本多的那一类

> ⚠ 摄像头只能一个程序占用。如果后端 `camera_service` 正在采集（网页上「摄像头」开着），采集脚本会打不开设备。先在前端停止摄像头，或者停掉后端服务。

**如果已有现成图片**，可批量导入并统一尺寸：

```powershell
.\train_env\Scripts\python.exe train\collect_dataset.py --source import --from D:\photos
```

（`D:\photos` 下每个子目录名就是一个类别；若图片是平铺的，加 `--class apple` 指定归属）

## 四、第 2 步：数据集划分（7:2:1）

```powershell
.\train_env\Scripts\python.exe train\split_dataset.py --clean
```

输出 `dataset/split/manifest.json`，记录每类各分到多少张。随机种子固定为 42，重跑结果一致，保证实验可复现。

**关于 LabelImg 标注**：这里要说清楚一件事——

| 任务类型 | 是否需要 LabelImg | 数据组织方式 |
|---|---|---|
| **图像分类**（本实验采用） | **不需要** | 按类别分文件夹，文件夹名即标签 |
| 目标检测（画框找位置） | 需要 | 每张图配一个 `.xml` 标注文件 |

报告 3.3 写「分类任务标注类别标签」，对分类来说「标注」就等于「分好文件夹」。LabelImg 是为检测任务准备的，本项目当前走分类路线，所以这一步可以跳过；如果老师要求必须体现标注环节，可以对 20~30 张图做一次标注并截图留档，在报告里说明「分类任务采用目录级标注，检测任务才需框选」。

## 五、第 3 步：训练

```powershell
.\train_env\Scripts\python.exe train\train_cnn.py --epochs 30
```

**关键参数**（报告 2.3 要求记录，这些就是可填的内容）：

| 参数 | 默认值 | 说明 |
|---|---|---|
| 输入尺寸 | 96×96×3 | 报告 3.2 指定；比 320×240 采集尺寸小，模型才能塞进板子 |
| 优化器 | Adam | 学习率 1e-3，ReduceLROnPlateau 自动减半 |
| 损失函数 | 交叉熵 | SparseCategoricalCrossentropy |
| Batch size | 32 | |
| Epochs | 30 | EarlyStopping patience=10，验证集不涨就提前停 |
| Dropout | 0.3 | 抑制过拟合 |
| L2 正则 | 1e-4 | |
| 随机种子 | 42 | 保证可复现 |

**网络结构**（自建轻量 CNN，报告 3.2 可直接引用）：

```
输入 96×96×3
 → Rescaling(1/255)  归一化
 → Conv2D(16, 3×3) + ReLU → MaxPool 2×2
 → Conv2D(32, 3×3) + ReLU → MaxPool 2×2
 → Conv2D(64, 3×3) + ReLU → MaxPool 2×2
 → Conv2D(64, 3×3) + ReLU → GlobalAveragePooling
 → Dropout(0.3)
 → Dense(32) + ReLU
 → Dropout(0.18)
 → Dense(类别数) + Softmax
```

参数量约 6 万，INT8 量化后 200 KB 上下，H7 Plus 完全放得下。

若要试 MobileNetV2（报告 1.2 提到的结构）：

```powershell
.\train_env\Scripts\python.exe train\train_cnn.py --arch mobilenet --epochs 40
```

**产出**：
- `models/fruit_cnn.keras`（验证集最优权重）
- `models/metrics.json`（测试集准确率、混淆矩阵、每类 P/R/F1、PC 单张耗时）
- `models/training_curve.png`（loss / accuracy 双曲线，可直接贴进报告）
- `models/training_log.csv`（逐轮记录）

## 六、第 4 步：转换与 INT8 量化

```powershell
.\train_env\Scripts\python.exe train\convert_tflite.py
```

**这一步的核心限制**（报告里值得写，体现理解了嵌入式部署）：

OpenMV 的 `tf` 模块**只接受全整数量化模型**：输入 `uint8`、输出 `int8`、所有算子 INT8。只做「动态范围量化」（float 权重 + int8 计算）的模型，OpenMV 加载会报错。

脚本强制使用：

```python
converter.optimizations = [tf.lite.Optimize.DEFAULT]
converter.target_spec.supported_ops = [tf.lite.OpsSet.TFLITE_BUILTINS_INT8]
converter.inference_input_type = tf.uint8
converter.inference_output_type = tf.int8
```

并用 `dataset/split/train` 里的真实图片做校准（默认 100 张，不是随机噪声）——校准数据的分布直接决定量化后的精度损失。

**产出**：
- `models/fruit_float.tflite`（浮点版，PC 对照精度）
- `models/fruit_int8.tflite`（量化版，部署用）
- `openmv_script/fruit_int8.tflite` + `openmv_script/labels.txt`（自动同步）

脚本会自动检查大小是否 ≤5MB（报告 2.3 要求），并在超限时给出压缩建议。

## 七、第 5 步：PC 端验证

```powershell
# 单张图
.\train_env\Scripts\python.exe train\pc_infer.py --image dataset\raw\apple\apple_0001.jpg

# 摄像头实时（按 q 退出）
.\train_env\Scripts\python.exe train\pc_infer.py

# 顺便把结果推给后端，网页看板会实时出现记录
.\train_env\Scripts\python.exe train\pc_infer.py --report --server http://127.0.0.1:5000
```

**为什么要在 PC 上先跑一遍**：
1. 确认量化后没出现「全判成同一类」的退化
2. 拿到 PC 端单张耗时作为基准（板端会慢 5~20 倍）
3. 逐张看错判的图，判断是标签错了还是模型欠拟合

**这里的 API 辨析**（报告 3.3 第 4 点有误，可以写进「实验结论」作为发现的问题）：

| 环境 | 正确 API |
|---|---|
| PC（Python） | `tf.lite.Interpreter` |
| OpenMV 板端（MicroPython） | `tf.load()` / `tf.classify()` / `tf.detect()` |

原文档把 PC 端 API 写成了板端接口，照着写会报 `ImportError: no module named 'tensorflow'`。

## 八、第 6 步：部署到 OpenMV

1. 把 `openmv_script/fruit_int8.tflite` 和 `labels.txt` 拷到 SD 卡根目录
2. OpenMV IDE 打开 `openmv_script/nn_classify.py`
3. 改配置区的 `NET_MODE`、`WIFI_SSID`、`WIFI_PASSWORD`、`SERVER_HOST`
4. 点运行，IDE 下方串口会打印：
   ```
   [nn] 摄像头就绪 QVGA RGB565
   [nn] 加载模型 fruit_int8.tflite ...
   [nn] 模型加载完成
   [nn] 类别共 3 个：['apple', 'orange', 'banana']
   ```

**硬件前提（必须确认）**：

| 型号 | SDRAM | 能否跑模型 |
|---|---|---|
| OpenMV Cam H7 | 1 MB SRAM | ❌ 放不下 |
| **OpenMV Cam H7 Plus** | 32 MB SDRAM + 1 MB SRAM | ✅ 可以 |
| **OpenMV Cam RT1062** | 32 MB SDRAM + 1 MB SRAM | ✅ 可以 |

标准 H7 加载几 MB 模型会直接 `MemoryError`。报告 2.1 写的「H7/H9 系列」不准确——只有带外部 SDRAM 的型号能跑神经网络。

**板端脚本要点**：
- `sensor.set_pixformat(sensor.RGB565)`：模型按 RGB 训练，用 GRAYSCALE 会得到完全错误的结果
- `tf.load(MODEL_PATH, load_to_fb=True)`：模型直接放帧缓冲区，省一半 RAM
- `tf.classify(net, img, min_scale=1.0, scale_mul=1.0)`：关闭多尺度滑窗，单果实场景下更快
- 置信度 < 0.65 判为 `bad`，与后端 `min_confidence` 口径一致

## 九、与 Web 系统的对接

板端识别结果通过 `POST /api/device/report` 上报，字段与现有接口完全兼容：

| 字段 | 类型 | 说明 |
|---|---|---|
| `fruit_type` | str | 类别名，来自 labels.txt |
| `result` | str | `good` / `bad` |
| `confidence` | float | 0~1 |
| `area` | int | 目标像素面积 |
| `image` | file | 标记图（可选） |
| `X-Device-Token` | header | `openmv-device-2026` |

上报成功后：写 `sort_record` 表 → SocketIO 推 `new_record` → 网页看板实时刷新。这条链路已经在项目里跑通过，`nn_classify.py` 复用的是同一套协议。

## 十一、常见报错对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `Model is not fully quantized` | 转换时没设 `inference_input_type=uint8` | 用本项目 `convert_tflite.py`，不要手写转换 |
| 板端 `MemoryError` | 用的是标准 H7（1MB SRAM） | 换 H7 Plus / RT1062，或把模型压到 <500KB |
| 分类结果全一样 | 量化校准样本分布不对，或训练集里某类占了 90% | 补样本、检查 `manifest.json` 各类比例 |
| 摄像头打不开 | 后端 `camera_service` 占用 | 前端先停摄像头 |
| 准确率卡在 33%（三类） | 模型没学到东西 | 检查图片是否真的按类别分对了文件夹 |
| `labels.txt` 顺序与输出对不上 | 手动改了 `classes.txt` 但没重训 | 类别顺序以 `models/class_names.json` 为准（字母序） |
